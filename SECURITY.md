# Security policy

This project has no public deployment. GitHub private vulnerability reporting is the project's confidential security-reporting route: use the repository's **Security** tab, open **Advisories**, and select **Report a vulnerability**. The named security-response owner is Jawad Benhammou (`@Jawadbenhammoupro`), who is responsible for receiving and reviewing those reports privately. Do not include real personal data, generated contracts, credentials, or other sensitive information in public issues or pull requests.

Responses are best-effort when the named maintainer is available; there is no response-time guarantee or alternate responder. This is a one-maintainer repository/CLI/MCP project without staffed on-call coverage, and no second responder has accepted continuity duties. The project does not offer a confidential conduct-reporting route because it has no separate conduct responder or managed intake channel. Do not put sensitive conduct details in public issues or pull requests. GitHub's private vulnerability route is for security vulnerabilities only and does not create a hosted support service.

The offline export command reads document values from standard input. It does not transmit or retain those inputs separately; generated documents are written only to the explicit output path. PDF conversion uses temporary files and an isolated LibreOffice profile that are removed when conversion ends.

Security reports should state the affected version, reproducible steps, and potential impact without exposing third-party data. See [GitHub's private vulnerability reporting guidance](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately) for how to submit a report.
